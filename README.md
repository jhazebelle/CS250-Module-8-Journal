# CS250-Module-8-Journal

Through this project, I learned that interpreting user needs starts with listening carefully and translating those needs into clear, actionable user stories. Creating user stories helped me think from the user’s perspective and focus on what brings real value, not just what’s technically possible. When developing programs, I’ve learned to approach them iteratively, breaking down large goals into smaller, manageable tasks that can be tested and refined over time. I plan to continue using Agile processes like sprint planning, daily standups, and retrospectives because they keep communication open and progress visible. To me, being a good team member in software development means staying collaborative, dependable, and adaptable, sharing updates, asking questions when something’s unclear, and supporting teammates through challenges. Every role I experienced in this project reinforced how essential teamwork, transparency, and flexibility are in turning user needs into working, meaningful software.
